# 第四條線：兩場館套利（獨立於交易策略，2026-08-28 開線）

這條線跟 V7／流動性獵取／撤單流**本質不同，所以單獨一個家**：
那三條在「預測市場」，這條在「找同一個東西的兩個價」——不預測任何
東西，賺的是市場結構的錢。使用者定位：**量化以外的閒暇項目**，
哪裡有肉就去哪裡，一場一場打，不是要長期養的線。

## 隔離規則（跟交易系統的邊界，比照 agent-boundary 的精神）

- 這個資料夾的程式**永不 import** indicator/、jarvis、executor、
  任何交易路徑的模組
- 資金完全獨立：就算未來接錢包，錢也不進 OKX/Bitget 的帳戶體系，
  盈虧不進 V7 的權益快照
- 跟主系統唯一共用的兩樣東西：**研究進度看板**（prereg_publish.py
  裡的 0.75 條目）和**資料新鮮度檢查表**（freshness_board.py 盯著
  錄製檔有沒有斷）——都是唯讀的顯示層
- 錄價程式本體在 repo 外（`../entropy-arb`，第三方 clone，本機補丁
  不推回去）；**這個 repo 只放判斷**，不放執行

## 這條線怎麼運作（白話版）

同一個標的掛在兩個交易所，兩邊價格會互相漂。價差夠大時，貴的那邊
做空、便宜的那邊做多，方向風險互相抵銷，等價差收斂就是利潤。
肉的來源：新場館定價沒被磨平＋零手續費補貼期＋標的冷門。
死期：機器人進場把價差磨掉，或補貼期結束費率恢復——所以每個
戰場都是有期限的，重點是進得早、撤得果斷。

## 階段流程（每個戰場都走同一遍）

```
1. 偵察     照下面的偵察表打分，及格才進下一步
2. 只錄不做  跑錄價程式 ≥7 天（零憑證零錢），判決標準在看到資料前寫死
3. 判決     跑 premium_verdict.py——肉夠肥且前後兩半都成立才繼續，
            否則關掉，總成本≈零
4. 工程     下單程式碼逐行審、租場館同區的 VPS、斷腿處理、
            決定放多少錢（這步之前不碰任何錢包）
5. 收割＋盯撤退訊號  價差窗口縮到亞秒級 or 費率恢復 = 收攤換戰場
```

## 偵察表（找戰場的五個條件，2026-08-28 凍結）

| # | 條件 | 為什麼 |
|---|---|---|
| 1 | 場館上線 < 3 個月 | 做市商還沒進駐，定價粗糙 |
| 2 | 零費率或積分補貼期 | 成本門檻歸零，薄價差也是淨利 |
| 3 | 同標的在別處有對照價 | 有東西可以對鎖，不然是裸賭 |
| 4 | 標的冷門（股票/指數/商品永續 > 主流幣） | BTC 的價差毫秒級就被吃掉 |
| 5 | 還沒發幣 | 衝量補貼最兇的階段 |

打分規則：五格逐一填「是/否＋證據」，**先填表再看盤面**，
不准被「聽起來酷」帶著走。≥4 分才值得開錄。
