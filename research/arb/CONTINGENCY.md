# 極端行情與斷腿：現在真的會發生什麼（2026-09-04）

> 使用者問：「今天如果遇到極端行情或是斷腿，應變措施是什麼？」
> 本檔逐情境寫**程式現在的實際行為**（不是設計意圖），並標出還缺的。
> 每一條都能在 `entropy_arb/engine.py` 找到對應的行。

## 1 斷腿（一腿成交、一腿沒有）——**有自動處理**

```
兩腿同時送出（asyncio.gather）
  → 一腿成交、一腿沒有 → net ≠ 0
  → _maybe_hedge() → _hedge()：在有部位那一側下 reduce-only 吃單平掉
      · reduce_only=True     永不開新倉
      · 跳過 book 過期或 venue_down 的場館   不盲目下單
      · hedge_slippage_bps 價格保護
      · 量太小平不掉 → carry，等下次對帳重試
  → 對沖失敗 → 記 error + 觸發對帳（讀鏈上真相，不猜）
  → 差額仍長大超過 max_net_base → HALT
```

**這一條是完整的。** 斷腿的標準結局是「幾秒內把成交的那腿平掉」，不是裸著。

## 2 HALT 之後——**2026-09-04 改正了語意**

**改正前**：HALT 停掉一切，包括對沖 → 斷腿的裸露**留在原地不動**。
`max_net_base` 那條特別自相矛盾：因為兩腿分家而停機，然後停止把它們合回去。

**現在**：

| HALT 擋什麼 | HALT 不擋什麼 |
|---|---|
| 開新套利（`_evaluate` / `_execute`） | **reduce-only 平掉既有裸露** |

平裸露有次數上限 `halt_flatten_attempts`（預設 3），避免失敗的對沖無限迴圈。
設 0 ＝ 完全凍結（保留原行為，可選）。

**為什麼這樣安全**：`_hedge` 是 `reduce_only`（永不開倉）、跳過過期或 down 的場館、
守場館鎖——**它不會盲目下單，只會讓部位變小**。

## 3 極端行情——**這是目前最弱的一環，要誠實說**

| 情境 | 現在會怎樣 |
|---|---|
| 價格劇烈跳動、但兩邊 book 都新鮮 | **照常交易**。沒有波動熔斷 |
| 一邊 feed 死掉（REST 還活著） | `is_fresh` 擋下單；**連續 N 次過期 → HALT**（今天加的 `max_consecutive_stale`） |
| 場館 API 整個掛掉 | 連 3 次抓不到部位 → `venue_down`，**只暫停該場館**，每 30 秒探測 |
| 被限流 | `_mark_limited` + 暫停，排序時降級 |
| 保證金不足被拒 | 記 `margin rejection — collateral exhausted` |
| 帳戶被強平 | **偵測不到**。下次對帳會看到部位變 0 並採信它 |

**缺的是波動熔斷**：目前沒有任何規則說「價格在 N 秒內動超過 X% 就停手」。
在 $50 規模下這不致命（總曝險 $300、1× 槓桿、無強平），但**放大之前必須補**。

## 4 現在的守衛全表（每一條都 O(1)、不做 I/O）

| 守衛 | 觸發條件 | 動作 |
|---|---|---|
| `is_fresh(staleness_sec)` | 任一腿 book > 10 秒 | 不下單（暫時） |
| **`max_consecutive_stale`** | 連續 N 次過期 | **HALT** |
| `venue_down` | 連 3 次抓不到部位 | 暫停該場館，每 30 秒探測 |
| `_venue_limited` | 被限流 | 暫停該場館 `rate_limit_pause_sec` |
| `cap_usd`（逐場館） | 單場館部位超額 | 不開新倉 |
| **`max_gross_usd`** | 兩腿名目合計超額 | **HALT** |
| **`max_net_base`** | 兩腿差額超額 | **HALT** |
| **`max_daily_loss_usd`** | session MTM 跌破 | **HALT** |
| `max_consecutive_errors` | 連續執行錯誤 | **HALT** |
| `orders_per_min` | 送單過頻 | 該場館暫停送單 |
| **`_recorder_dead`** | 錄價 task 死亡 | 告警＋狀態行，**不停交易** |

粗體是 2026-09-04 加的。實測成本：全部合計 **< 2 µs**。

## 5 $50 規模下的最壞情況

| 風險 | 在 $50/所、1× 槓桿下 |
|---|---|
| 強平 | **不可能**（無槓桿） |
| 斷腿裸露 | 上限 = 一筆的名目（$50） |
| 場館違約 | 輸該所餘額（$50） |
| 全部同時出事 | **$300**（總曝險上限） |

**所以現階段真正的風險不是錢，是程式**——而程式的兩個致命形狀（資料過期後補單、
差額無聲長大）現在都有守衛了。

## 6 還缺的（照優先序）

- [ ] **波動熔斷**：N 秒內價格動超過 X% 就暫停開新倉。放大規模前必須有
- [ ] **強平偵測**：現在只能靠對帳事後發現部位變 0，不會告警
- [ ] **TG 控制通道**（B5）：`pause` / `resume` / `flat` / `size` 四個動詞——
      **`flat` 是「極端行情時人要能一鍵平掉」的那個動作**，現在只能手動上網頁
- [ ] **停機後的通知**：現在只有 log 與狀態行，沒有推播。半夜 HALT 沒人知道
