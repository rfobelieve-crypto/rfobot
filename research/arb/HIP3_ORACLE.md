# HIP-3 是什麼，以及 Entropy 的 oracle 設計對套利的意義（2026-09-04）

## 1 HIP-3 是什麼（官方文件）

**任何人都可以在 Hyperliquid 上部署自己的永續市場。** 規則：

- **質押 500k HYPE**（主網門檻，預期隨時間下降），且**部署後至少維持 183 天**
- 一個部署者一個 dex；**前 3 個標的免拍賣**，之後走荷蘭拍（與 HIP-1 同一套參數）；
  部署者另有 `7 + 0.2 × n` 個保留名額可用當前拍賣價直接上，跳過計時
- **部署者控制**：市場定義、**oracle 價格**、槓桿上限、合約規格，以及 `haltTrading`
- **費用分成 0–300%**（growth mode 0–100%）；超過 100% 時協議費同步提高
- **oracle 在協議層是完全開放的**——文件只「建議」選難以操縱、有經濟意義的來源

**所以 HIP-3 的核心是：交易所的撮合、清算、保證金引擎由 Hyperliquid 提供，
而「這個市場的價格是什麼」由部署者定義。** 我們掃描器裡的 io（Entropy）、
xyz（TradeXYZ）、para、mkts 全是這樣的 dex，共用同一條鏈與同一套風控引擎，
但**各自有自己的 oracle**。

## 2 使用者觀察到的 Entropy oracle 設計

> 根據訂單簿深度動態調整「市場自身價格」與「外部價格」的權重——流動性越好，
> 市場自身的定價權越高；當流動性夠好時 oracle 更接近市場價，
> **mark 與 oracle 的偏離變小 → 資金費率變低**。

各 dex 的 |funding| 中位（bps/8h）：

| dex | 標的數 | \|funding\| 中位 |
|---|---|---|
| **io（Entropy）** | 7 | **0.208** |
| mkts | 23 | 0.000 |

io 確實低於 HL core 與 xyz——**但這個比較不成立**：n=7 對 n=233、而且資產類別不同
（加密的資金費結構性高於股票）。mkts 是 0.000 更低，但它 OI 全是 0（沒人交易）。

**乾淨的檢定是同一標的跨 dex**（25 個標的出現在 ≥2 個 dex）：

| 標的 | dex | funding | mark−oracle |
|---|---|---|---|
| ANTH | **io** | **+0.012** | +1.5 bps |
| ANTH | para | +0.000 | 0.0（OI=0，沒在動） |
| AVGO | xyz | +1.001 | +4.7 | 
| AVGO | para | **+6.523** | +2.8 |
| CRWD | xyz | +0.500 | +4.2 |
| CRWD | para | +3.136 | +0.8 |

**結論：方向對，但證據薄。** io 唯一有 OI 的重疊標的（ANTH）funding 幾乎是 0，
確實極低；但可比的樣本只有一個。而 para（OI 也小）的 funding 反而最高——
**說明 funding 高低不只是 oracle 設計，還混著流動性與 OI**。
真要驗這個假設，需要的是**同標的、同時段、OI 都非零**的配對，現在只有 ANTH 勉強算。

## 3 對套利的兩面意義（這一節是重點）

### 正面：低資金費 = 持有型套利的成本低

我們的成本函數第 4 桶（持有成本）＝資金費差 × 持有時間。io 的 funding 接近 0
表示**在它上面持倉幾乎不用付租**。這對 **cash-and-carry／基差交易**有意義。

但對我們**現在**做的東西沒有意義：§1.07 已經量過，收斂中位 5–15 分鐘的持有時間下
**carry 進不了帳**（消融證明增益全來自出場目標，不是 carry）。**低 funding 要能變成
優勢，前提是把持有時間拉長到以天計**——那就是另一種策略、另一本風險簿。

### 反面（而且更重要）：oracle 貼近自己的簿口 = 拉回市場的力量變弱

資金費率是**把 mark 拉回 oracle 的機制**。如果 oracle 本身跟著自己的簿口走，
那麼「這個 dex 的價格偏離外部世界」時，**沒有任何力量把它拉回來**——
funding 低不是因為價格對，是因為**它把自己的價格當成對的**。

對套利的直接後果：**io 上的價差更可能是結構性偏移，而不是會收斂的價差。**
這正是 §0.75 的收斂關要擋的東西，也是 BTC 對照組（$97.8/天但 episodes=0）教我們的事。

**一個要注意的細節**：我們的收斂關量的是「溢價回到自己的 6h 滾動中線」——
如果兩個場館一起漂，中線跟著漂，**收斂關會過，但錢賺不到**。
io 的家族目前收斂率 98–100%，看起來很好；**但那是相對自己的中線**。
要區分「真收斂」與「跟著漂」，需要一個**外部錨**（真實股價），而那正是 §1.10
待辦裡「HIP-3 vs 真實市價」那條腿要回答的問題。

## 4 使用者提的 UI 建議（把 oracle 組成比重可視化）

這是對 Entropy 的產品建議，不是我們要做的東西。但它指出一件對我們有用的事：
**oracle 的權重是可觀測的**——如果 Entropy 願意公開即時權重，那就等於公開了
「這個價格現在有多少是市場自己說的」。對套利者來說，**權重高＝偏移不會被拉回**，
那是決定要不要進場的一級資訊。在他們做出來之前，我們的替代品是外部錨。
