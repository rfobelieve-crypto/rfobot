每一條都對到這個 repo 裡的真實定義與數字，不是通用術語表。格式一律是：

參數會變。如果哪裡對不上程式碼，以程式碼為準，並回來修這份文件。

## 一、模型與訊號

**V7 / Dual Model**
兩個各自獨立的 XGBoost 回歸模型，不是一個模型做兩件事。
`Direction`（136 特徵）預測 4 小時後的路徑報酬 `pred_return_4h`；
`Magnitude`（72 特徵）預測同期間的**絕對**變動幅度 `|return_4h|`。
分開的理由：「往哪走」跟「走多遠」是兩個問題，各自有各自的驗證。

**y_path_ret_4h（預測目標）**
`mean(close[t+1..t+4]) / close[t] - 1`。
注意是**未來 4 根 bar 收盤的平均**（TWAP 路徑報酬），不是第 4 根的單點收盤。
用平均是為了讓目標不被單一根的雜訊主導。

**pred_return_4h**
模型輸出的連續預測值，正負代表方向、大小代表強度。
系統裡幾乎所有判斷都源自這個數字——包含新的 `conviction_decay` 出場。

**Rolling percentile 解碼**
把連續的 `pred_return_4h` 轉成 UP / DOWN / NEUTRAL 的方法。
維護一個 **500 根**的預測值緩衝區（`PCTILE_WINDOW=500`），拿當前預測跟這 500 筆比排名：
- 落在最極端的 **5%**（`STRONG_FRAC`，雙邊各 2.5%）→ **Strong**
- 落在最極端的 **15%**（`MODERATE_FRAC`）→ **Moderate**
- 其餘 → NEUTRAL
重點：**Strong 是相對排名，不是絕對保證**。它的意思是「這個預測比近期 95% 的預測都極端」。
（`research/v71_v7_sizing_1x.py::decode_signals`，與生產推論同一套邏輯）

**絕對值下限（ABS_FLOOR）**
低波動時期的保險。純用百分位會有問題：如果最近所有預測都很小，
「前 5%」可能只是「0.0001 vs 0.00008」這種無意義的差別。
所以額外要求 Strong 的 `|pred|` 至少 **0.0008**、Moderate 至少 **0.0005**，
兩個門檻取較嚴的那個。

**Warmup（暖機）**
緩衝區還不到 **100 根**（`WARMUP_BARS`）時，改用寫死的 fallback 門檻。
（歷史教訓：這個緩衝區曾被別的腳本覆寫成空的，導致系統長期用 fallback
門檻、狂發 DOWN 訊號。詳見 `mistake.md` 2026-04-19。）

**Confidence（信心分數 0–100）**
`min(|pred| / Strong_cutoff, 1.0) ^ 0.6 × 100`。
純粹是「這個預測相對 Strong 門檻多強」的換算，**不是機率**。
80 分不代表 80% 會對。（2026-05-09 移除了原本的 magnitude 加成，因為
樣本外顯示高 magnitude 的 bar 反而落在模型失靈區。）

**Regime（市場狀態）**
CHOPPY / TRENDING_BULL / TRENDING_BEAR / WARMUP 四種，是模型的一個輸入特徵，
也顯示在圖表上。它描述「現在是盤整還是趨勢」，不預測方向。

**SHAP 驅動因子**
每次出 Strong 訊號時，用 TreeExplainer 回答「這次是哪幾個特徵把預測推上去的」。
存在 `tracked_signals.shap_top`。這是解釋性，不是額外的預測。

## 二、驗證方法（這套系統的核心紀律）

**IC（Information Coefficient）**
預測值與實際報酬的 **Spearman 等級相關**。衡量「排序對不對」而不是「數值準不準」。
量化上 IC 0.05 已算可用，0.15 算強。本系統近期 walk-forward OOS 約 **+0.154**。

**AUC (sign)**
只看方向對錯的區分能力。0.5 = 硬幣。本系統約 **0.59**。
重要認知：AUC 0.57 的結構下，top-5% 精準度的**數學上限**大約 68–72%，
所以「Strong 勝率 95%」這種目標在這個模型結構下**永遠達不到**
（`mistake.md` 2026-04-14 的教訓：目標要從 AUC 反推，不是拍腦袋定）。

**Walk-forward（滾動前向驗證）**
唯一被接受的驗證方式。每個測試點的模型**只能看到該點之前的資料**，
訓練→測試→時間往前推→重新訓練，重複 77 次（77 folds）。
禁止用「已經吃過全部資料的生產模型去預測過去」，那叫 in-sample，零資訊量。

**Purge / Embargo**
防資料洩漏的兩道措施，因為標籤是前瞻 4 小時的：
- **Purge = 4**：訓練集尾端砍掉 4 根，因為它們的標籤窗會伸進測試區
- **Embargo = 4**：訓練與測試之間再空 4 根，避免波動叢聚造成的鄰接汙染

**In-sample 陷阱**
用訓練時已看過答案的模型去評估過去。會產出漂亮但無意義的數字。
實例：同一個月，in-sample IC 0.60 vs 乾淨 walk-forward IC 0.10。

**Conditional IC（條件 IC）**
新特徵能不能加進模型的**正確**篩選指標：不是看它跟目標的相關（raw IC），
而是看它跟 **V7 預測殘差**（`y - pred`）的相關。
理由：一個特徵可以跟目標很相關，但那些資訊 V7 早就從別的特徵吃到了，
加進去等於雜訊。只有「V7 沒抓到的部分」才有價值。
（`mistake.md` 2026-06-01：21 個特徵 univariate IC 漂亮，ensemble 零提升。）

**Ensemble A/B 的 4 條關卡**
即使 conditional IC 過關，要真的部署還得同時滿足：
1. Aggregate AUC lift > 0.005
2. **每個 fold 各自算的 lift 平均 > 0.001**
3. 正向 fold 比例 > 55%
4. Bootstrap 95% CI 不含 0
第 2、3 條的存在理由：aggregate 指標會被 1–2 個極端 fold 撐起來。
實例：WQ101 那次 aggregate +0.0072（看起來過關），但 per-fold 平均是 **−0.0044**。

**Bootstrap 信賴區間**
把樣本重複抽樣幾千次，看統計量的分布。
用途是回答「這個數字有多不確定」。
本系統的規則：**點估計不算證據，要看 CI**。小樣本的 CI 常常寬到包含硬幣線。

**月一致性**
把同一個統計量分月計算，看正負號是否穩定。
陷阱：如果窗口只涵蓋一個月，這個指標恆為 100%，等於沒驗。

## 三、Gate A / Gate B（能不能加碼的判準）

把兩個不同的問題拆開，各用最有統計力的資料回答：

**Gate A — edge 是真的嗎？（統計問題）**
用累積的 `tracked_signals` 訊號回填結果（數百筆），不是用實盤損益（數十筆）。
門檻：Strong 訊號勝率的 bootstrap **95% CI 下緣 > 52%**（顯著高於硬幣）。
狀態會隨資料漂移，**每次要加碼都必須當下重跑**，不能引用上次的 PASS
（2026-06-14 跑出 59.0% PASS，06-19 同一支確定性腳本重跑變 57.6% FAIL，
純粹是多了 4 天資料）。

**Gate B — 執行有沒有把 edge 吃掉？（操作問題）**
用 30–50 筆乾淨實盤交易，要求全部成立：扣成本後 net ≥ 0、
0 次 kill trigger、trailing stop 確認真的在交易所上移、
實盤每筆報酬落在回測分布內。目前進度 14/30。

為什麼要拆：薄 edge + 高方差 → 30–50 筆實盤的勝率信賴區間寬到含硬幣線，
用實盤損益證明 edge 存在是**最沒效率**的做法。

## 四、執行與風控

**Stage（資金階段）**
從 Stage 0（純指標）到 Stage 4d（$10k+）的漸進階梯，每一階有金額上限、
槓桿上限、與進階條件。目前 **Stage 3**，基準資金 $1,218.44。
原則：**金額大小 × 風控深度，要對齊 edge 的確信度**。

**Informed override**
明知故犯地違反自己先前訂下的規則，但**寫下來**：為什麼、違反了哪一條、
代價是什麼、什麼情況下要收回。目前累積 6 次，全部記在 `CLAUDE.md`。
存在意義是讓「破例」有成本、可追溯，而不是悄悄漂移。

**有效槓桿 vs 帳戶槓桿**
兩個不同的東西，混淆會出事：
- **帳戶槓桿 10x**：OKX 那邊的設定，只決定「鎖多少保證金」
- **有效槓桿 2x**（`NOTIONAL_LEV_MULT`）：名目部位 ÷ 權益，這才是**真實風險槓桿**
名目 = 2 × equity，隨帳戶自動縮放（賺多下多、虧多下少，不會 leverage creep）。

**Kill switch（寫死在程式碼的強制風控）**
不是靠紀律，是 executor 會直接拒絕動作。主要代號：

| 代號 | 觸發條件 | 動作 |
|---|---|---|
| `CAP-2` | equity > 1.5 × 基準資金（意外注資）| HALT |
| `CAP-3` | 單日虧損 ≤ −20% | HALT |
| `CAP-4` | 累計虧損 ≤ −30% | DEMOTE（終態，需人工）|
| `A1` / `A3` | 私有 WS 心跳過期 | DEMOTE |
| `A2` | 連續重連失敗 | DEMOTE |
| `A4` | 對帳不一致 / 無法對帳 | HALT |
| `B4` | 停損單放置延遲過久或無回應 | DEMOTE |
| `C5` / `C6` | NTP 時鐘偏移 > 5s / > 30s | HALT / DEMOTE |
| `E4` | API key 權限不符（多或少）| 拒絕啟動 |
| `MANUAL-INTERFERENCE` | OKX 上有 executor 沒開的倉 | DEMOTE |
| `PRESUBMIT-LEV` | 送單前算出的有效槓桿超過上限 | 拒送 |
| `MAX-POS` | 本地 DB 開倉數超過 1 | 拒送 |

**HALT vs DEMOTE**
`HALT` = 暫停，觸發條件消失後下一輪自動回 ACTIVE。
`DEMOTE` = 終態，必須人工介入（重啟服務或處理根因）。

**對帳（Reconciliation）**
每個 cycle 比對「本地 DB 認為的部位」vs「OKX 實際部位」。
四種結果：CONSISTENT / `orphan_local`（DB 有、交易所沒有）/
`orphan_exchange`（交易所有、DB 沒有）/ size 或方向不符。
原則：**交易所是真相來源**，本地只是鏡像。

## 五、進出場

**進場**
只吃 **Strong** tier（`OKX_STRONG_ONLY_ENTRY`）。
Moderate 不交易——理由是在 `max_position_count=1` 的限制下，
開 Moderate 會佔掉唯一的部位槽，擋掉後面更高品質的 Strong。

**出場（四條，有優先序）**

| 機制 | 條件 | 說明 |
|---|---|---|
| `time_cap` | 持倉超過 N 小時 | **目前關閉**（設 0）。曾設 72h，但實測會把最大的贏家提早砍掉 |
| `conviction_decay` | 模型原始輸出**連續 2 根 bar** 與持倉方向相反 | 2026-07-25 上線。用進場模型的連續輸出持續判斷「當初進場的理由還在嗎」 |
| `opp_signal` | 出現反向的 Strong 訊號 | 比 conviction_decay 嚴格（要完整反向分級）|
| `trail_stop` | 3 × ATR 移動停損 | 掛在 OKX 上的真實 algo 單，隨新高/新低上移 |

**MFE / MAE**
持倉期間的**最大未實現獲利** / **最大未實現虧損**。
用途：診斷「賺到的有沒有被吐回去」。實測 trail_stop 出場平均回吐 MFE 約 2.56%。

**Shadow mode（影子模式）**
新機制上線前的觀察期：**照常計算、記錄它「會怎麼做」，但絕不真的執行**。
用結構上的程式碼隔離保證（不呼叫 `_close_position`），不是靠設定。
目的是累積真實環境的證據，再決定要不要讓它接管。

## 六、資料與撤單流

**訂單流（Order flow）**
成交與掛單的細節，不是價格本身。包含 CVD、taker 買賣失衡、
大單、深度簿變化等。核心假設：價格往阻力小的方向走，
而阻力可以從掛單/撤單看出來。

**CVD（Cumulative Volume Delta）**
累計的「主動買 − 主動賣」。衡量誰在追價。

**Taker ratio**
`delta_usd / volume_usd`。這根 bar 的成交裡，淨主動買佔多少比例。

**撤單流（Cancel flow）**
`depth_deltas_1m` 每分鐘記錄買賣兩側的掛單新增/取消量。
假設：撤單比成交更早洩露意圖——真要拉抬的人會先把上方賣單撤掉。
**這條線是純研究，永不接自動下單。**

**shock / vshock**
相對自己近期基準的倍數，用來定義「異常」：
- `shock` = 這分鐘總撤單量 ÷ 前 60 分鐘中位數
- `vshock` = 這分鐘成交量 ÷ 前 60 分鐘中位數

**撤單劇本（凍結定義 v1，2026-07-16）**
機器每分鐘自動分類，`shock ≥ 3` 才進入判斷：

| 劇本 | 條件 | 判讀 |
|---|---|---|
| 吸收 `absorption` | 量爆 + taker 失衡 + **價格守住**（≤5bps）| 反轉 |
| 真破 `true_break` | 量爆 + taker 失衡 + **價格動了** | 順勢 |
| 真空 `vacuum` | 量沒爆但單側被抽穿 | 順勢（v1 定義下實際 0 次觸發）|
| 雙側避險 `two_sided` | 兩側均勻撤單 | 無方向 |
| 純爆量 `gate_only` | 過門檻但都不符 | 無方向，當統計分母 |

**撤單先行 `vacuum_lead`（v3，暫定非凍結）**
專門測「單側掛單被抽走**領先**價格」這個核心假說：
被抽側撤單 ≥ 3× 自己中位數，**且** ≥ 2× 對側，
**且** 成交還沒跟上（vshock<3），**且** 價格還沒動（≤5bps）。
最後兩個條件是重點：不加的話測到的是「跟隨」而不是「領先」。

**def_version（定義版本）**
偵測定義一旦上線就凍結。要改門檻必須開新版本號，
**舊資料永不重貼標籤**。理由：看了結果再回頭調定義 = overfit。

## 七、常見誤解（值得單獨列出）

**「訊號準確率」≠「交易會賺錢」**
Gate A 證明的是方向判斷有 edge，Gate B 才證明扣掉成本與停損後能變成正收益。
本系統目前訊號層勝率約 60%，但實盤 14 筆的淨勝率 43%、累計 −0.80%。
兩個數字都是真的，差別在成本、停損時機、與樣本量。

**「回測漂亮」≠「有效」**
最常見三個陷阱：用生產模型評估過去（in-sample）、
用 fold 模型的輸出去校準生產模型（分布尺度不同）、
只看 aggregate 指標（會被極端 fold 撐起來）。

**「零筆事件」≠「市場平靜」**
偵測器沒有輸出，可能是「真的沒發生」，也可能是「條件邏輯上不可能成立」。
兩者在儀表板上長得一模一樣。實例：v2 撤單先行跑了 36 小時 0 筆，
根因是把「比例」與「絕對倍數」AND 在一起，兩者互斥。

**「服務是綠的」≠「功能正常」**
最危險的故障是進程活著但邏輯已死。實例：移動停損因為缺一個參數，
從上線起就從未在交易所真的生效；出場通知因為一個 `_` 破壞 Markdown，
從上線起一封都沒送出去過。兩者都不會讓程式崩潰。

## 掃單失敗反轉（策略 #2「流動性獵取」，2026-07-28 凍結）

**流動性池（四種）**
價格前方訂單堆積的參考位，全部因果建立（形成當下就固定，不用未來資料）：
波段樞紐（±10 根確認的高低點）、時段極值（亞洲/倫敦/紐約，收盤生效）、
昨日高低（PDH/PDL）、上週高低（PWH/PWL）。定義在
`research/sweep_failure/level_types.py`。

**獵取（sweep / raid）**
1H K 棒掃穿池子價位。之後 8 根內回踩原價位 → 反向進場（fade）；
沒回來 → BREAKOUT，不追。出場 = 3.5×ATR 停損或 8 根時間出場。

**變體 A**
原始凍結版：只用波段池、無濾網。Gate F 的正式受測軌道
（`sweep_forward.py` 每月計分）。

**變體 B**（2026-07-29 預註冊）
四種池全開 ＋ 唯一濾網「掃單棒穿越 ≤ 0.25 ATR」（淺穿越＝假突破形）。
研究依據：穿越三桶單調、11/11 季正、33% 交易佔 84% 利潤、四種池上各自
獨立成立。Forward 門檻：n≥1400 且日聚類 bootstrap CI 下緣 > 0。
圖表上亮色進場 ▲▼ 與表格 B 欄 = 這個子集。

**變體 C**（2026-07-31 註冊，觀察 cohort）
C = 變體 B ∧ 收回內側（flow_reject=1：獵取那一小時內 1m **收盤價**
回到價位內側）。注意：這是**分鐘級價格路徑**確認，嚴格說不是訂單流——
真訂單流欄位（量能倍數、追價佔比、吸收，BTC 另有 OI×CVD）只記錄不進
判斷，屬於十月預註冊的驗證範圍。**刻意零數值門檻**——量能倍數跨幣尺度不可比（全籃中位
9.4x vs BTC/ETH 研究 ~3x），任何固定數字都是調參；量能原始值照記，
十月預註冊再驗。C 不改 A/B、不承諾升級，要自己的 forward 證據才能變
可交易規則。表格 C 欄 = 這個子集。

**變體 D**（2026-08-01 註冊，觀察 cohort）
D = 變體 C ∧ 量能高 = 研究收斂的**訂單流反轉組合**（收回∧量能）。
量能高 = 該筆 vshock ≥ **該幣自身**此前所有已記錄獵取的 vshock 中位數
（因果：只用更早的筆；零參數：中位數；≥5 筆先例才判定）。跨幣尺度問題
