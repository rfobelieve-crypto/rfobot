## 1. Analysing Real Fills（2026-05-27）

**他做了什麼**
在 Binance 線性永續的前 50 標的上，用低延遲做市程式雙邊掛單「乒乓」book，
四天收集約 **35,000 筆真實 maker 成交**，用 5 秒 markout 量成交品質。

**他主張**
1. **絕大部分的逆選擇在「你還不知道自己成交了」之前就已經實現。** 成交之後
   才發生的逆選擇很小。
2. **掛得越遠，markout 顯著越好。**
3. 標的原本的價差**對 markout 沒有顯著影響** → 流動性越差的標的，
   maker 相對 taker 的經濟性越好。
4. markout **沒有明顯的時段性**（逐小時）。
5. 成交時間有**厚尾**；他猜厚尾與「你有沒有短線 edge」有關。
   注意他的量法：從**第一張**掛單算起，不是從真正成交的那張算起——
   換成後者分布就不那麼偏。

**對照我們的**

這一則同時**解開一個懸案**與**擋掉一個誤用**。

*(a) 解開懸案*：`resting_limit.py` 量到掛在價位的誠實淨值 **−0.0626 R**，
被動成交那半 **−0.0612**（n=3,311）。2026-09-07 我曾用「佇列位置」解釋它，
被使用者正確駁回（沒有簿口資料、規模也不適用），後來 `nofill_distance.py`
證明**未成交是因為價格沒回來**（>10 tick 佔 87.8%、中位 108 tick、
「碰到沒穿」0 筆）。但那隻解釋了**沒成交的那些**，沒有解釋**成交的那些為什麼是負的**。
他的第 1 點給了機制：**成交本身就是逆選擇的結果**，而且在你知道之前就發生了。
兩片拼起來，−0.0612 不需要佇列論就能完整解釋。
→ **可驗**：`resting_limit.py` 已經有逐筆成交時點，加一欄 5 秒 markout
（用 `poc/data/bars` 的分鐘 bar 近似）就能看我們的被動成交是不是同一個形狀。

*(b) 擋掉誤用*：他的第 2 點「掛得越遠 markout 越好」**不可以直接套到我們身上**，
而且我們有反向的實測。`resting_limit.py` 的 delta 掃描是
**0.00 → 0.10 ATR 單調變差**（−0.0626 → −0.0762）。
不是矛盾，是**量的東西不同**：
  - 他量 **markout**（條件在「已成交」上）——那是執行品質
  - 我們量 **每事件淨值**（含未成交）——掛得越遠，成交率 87.7% → 85.4%，
    而**掉的那些正是價格一去不回的贏家**
→ 一句話：**「掛遠一點」是做市的經濟學，不是方向性進場的經濟學。**
   這條差異要寫進 §1.02 旁邊，否則下一個人看到這篇會想去放寬 delta。

*(c) 對鏈上線的方向性含意*：他的第 3 點說**流動性越差，maker 越划算**。
HL 主場 234 個市場裡長尾很薄——這是少數幾個「去效率低的地方」同時
**改善**執行經濟性的論點，跟「低競爭＝低容量」那個代價是分開的兩件事。
→ **可驗**：HL 的 `book/*.json` 有每檔**張數**（`n`），這是 CEX 公開資料沒有的欄位。
   等 tape 累積夠，可以直接量「掛在第 k 檔的成交率與 markout」。

*(d) 第 5 點的量法是一個我們沒做的切分*：他區分「從第一張掛單算」與
「從真正成交那張算」。我們的 `resting_limit` 目前沒有這個區分（只有成交/未成交）。
**快成交 vs 慢成交的 markout 差異**是一個不需要新資料就能跑的切分。

## 2. Lessons from the Desk（2026-06-29）

**他主張**
研究營運只有四件事：人、工具、資料、以及把三者串起來的**急迫感**。

工具那節他列了五條「絕對不准」：
1. 不准手動抓你早就知道會用到的資料——全部進每日 cron
2. **不准為每個 alpha 寫一個回測器**。回測器要標準化、進函式庫；
   它處理不了新的 alpha 形式就**升級它**，不要開第二個
3. **常一起用的資料要事先合併好**，用 cron 產出合併檔，不要每次迴圈過濾
4. **不准在工具之外載入資料**。要有一個 loader：給標的、日期範圍、
   資料型別、供應商就載好。（他順帶給了兩個實測較快的選擇：
   CSV 用 `pd.read_csv(engine="pyarrow")`、parquet 用 **Polars**）
5. 建 notebook 樣板

資料那節：好資料要同時做到**存在、正確、好用**。其中
「**存在**」最重要，而且——**最好收集的資料是最容易收集的那種，通常就是即時資料**。
「正確」＝給資料寫測試，像單元測試一樣查異常。
「好用」＝檔案層級要分桶（能只讀某個日期/標的），常用的過濾結果另存一份。

他還給了一個反面案例：某家把時序資料丟進 DynamoDB，長到 TB 級之後
每月 $30,000 而且**不能用**，因為查詢要掃全庫。

**對照我們的**

*(a) 我們已經比他嚴格的部分*：「資料要寫測試」這條我們做得更深——
`freshness_board`（48 列）、`coverage_audit`（宣告 vs 實有）、
每個守衛要**綠一次也紅一次**的反向證明。這篇沒有提到預註冊或反向證明。
**不要從這篇學驗證方法，我們在這件事上領先。**

*(b) 他的第 2 條是我們最貴的那個病的架構解**——這是這篇最有價值的一句。
我們有 `sweep_core`、`conj_backtest`、`poc/*`、`resting_limit`、`honest_fill`
各自帶自己的成交與損益邏輯。而 mistake.md 裡最貴的一類就是
「第二份實作會安靜地不同意」（2026-09-07 `conj_watch` 五個 bug、
2026-08-26 看板把 1127 顯示成 346）。
我們一直把它當**紀律問題**處理（「記得呼叫同一顆」），
他的規則說它是**架構問題**（一開始就不要有第二個回測器）。
→ **可做**：把成交/損益的那一層抽進 `research/harness.py`，
   讓所有回測腳本只保留「事件定義」與「進出場規則」。
   這不是重構潔癖——它會**在構造上消滅**那一整類 bug。

*(c) 第 3、4 條我們沒做，而且有量得到的成本*：
`poc/data/bars` 是一幣一檔各 1,351,710 列、`.cache` 29 個 CSV，
每支分析腳本自己 glob、自己讀、自己合併。沒有統一 loader、沒有預合併檔。
→ **可做**：一個 `research/dataio.py`（symbol / 日期 / 型別 / 來源），
   parquet 改走 Polars。我們現在有 `freshness_board` 跑 3 分鐘、
   `coverage_audit` 跑 4 分鐘，兩支都是 loader 層可以吃掉的成本。

*(d) 「最好收集的資料是最容易收集的即時資料」——這條事後證明了 9/10 晚上的決定*。
HL 的四樣（逐地址部位、清算價、L2 簿口、成交帶）**沒有任何歷史端點**，
而即時是免費的。我們當晚做的就是這件事。
連帶：K 線可以回填但端點只保留 **5000 根/週期**（1h=208 天、1m=3.5 天），
所以分鐘解析度**只能靠自己錄**。

*(e) DynamoDB 那個案例對上我們現在的容量問題*：
全庫 3.54 GB、78.9 MB/日，**7 張表完全沒有保留策略**（合計 1,495 MB），
其中 `depth_events_1s` 一張 1,205 MB（全庫 34%）、41.8 MB/日、而且只有 BTC。
他的教訓是「資料要存對地方，前處理要先做」。
→ 我們的版本是：`cleanup.py` 有守衛擋「宣告了保留卻沒 DELETE」，
   **但沒有反向守衛**擋「表在長卻沒有宣告保留」。那個盲區就是 depth_events_1s。

## 3. It's All Alphas（2026-03-08）

**他主張**
幾乎所有交易公司的 edge 都可以壓縮成某種 alpha 表示。他把管線畫成一串轉換器：

```
資料 -> alpha（特徵工程）-> 預測（forecasting/ML）-> 目標組合（最佳化）-> 交易（執行）
```

關鍵的區分是 **formulaic alpha（公式化，連續值）** vs **logical alpha（邏輯式，二元）**。
他認為邏輯式的效率差，因為它**跳過預測與組合最佳化兩個階段，直接吐出目標組合**，
而二元輸出很難接進管線。

另一句他講得很重：alpha 之後的每一層都是**乘數**，機器學習尤其是——
**2 × 0 還是 0**。沒有好特徵，複雜的 ML 救不了。

對**套利**他的看法跟一般寫法相反：不要用「價差 > X 就吃」的硬門檻，
那會逼你在跨過門檻的瞬間吃單。比較好的形式是**像做市一樣圍繞一個公允價
內部掛價**，這些報價不必真的掛出去，只在它穿過對手簿口最佳價時才送出成為 taker。
在這個設定下，「預測」就只是另一個交易所的價格。
他還補一句：這種情況**跨所對沖通常是次優的**，因為換手夠高、交易會在時間上互相平均掉。

以及一句對我們現在方向有關的：除非你找到一個**極度低效率的市場**——
而那種情況下，**找到並進得去那個市場本身就是 alpha**，因為它很罕見。

**對照我們的**

*(a) 這是對我們框架的直球，而我們已經獨立撞到它的三個症狀*：
**我們整套系統都是 logical alpha。** SDV＝三個旗標的合取、舊線＝觸價、
地形＝保留/否決、V7＝把連續的 `pred_return_4h` 切成 Strong/Moderate/Neutral
之後只交易 Strong。我們沒有 forecasting 層，也沒有 optimizer 層——
`max_position_count=1` 就是「最佳化」。

我們已經量到的三個症狀，一直被當成三個獨立問題：

| 我們的量測 | 他的框架下是什麼 |
|---|---|
| \|pred\| 五分位與勝率**無單調關係**（Q1 54.5% / Q3 59.1% / Q5 64.0%，2026-08-24） | 離散化把連續預測的資訊丟掉了，而且切點不在資訊所在的地方 |
| tier 進場擠出（開 Moderate 會佔掉 Strong 的槽，[[project_tier_entry_crowdout]]） | 沒有 optimizer，所以「要不要換倉」退化成先到先得 |
| 組合層要手工算（§1.07/§1.08，7 條線→3.49 有效、12 條→8.09） | 那就是 optimizer 該做的事，我們在外面手做 |

→ **這是一個框架級的假設，不是一個可以明天驗的參數。** 要驗它，最小的形式是：
   **拿 V7 的連續 `pred_return_4h` 直接當權重（不切 tier）跑一次組合層**，
   對照現行「只開 Strong、單倉」。兩者的樣本外夏普差距，就是離散化的成本。
   資料全部現成（`indicator_history` 3,781 列帶 `pred_return_4h`）。
   **注意這會動到既有判決的地基，所以要走預註冊，不准先跑再寫判準。**

*(b) 套利那段直接命中 §0.75 的形式*：我們那條線就是**硬門檻**
（帶＝可成交空間的 p90，穿過就記一次開火），而判決是「帶寬不夠付費用」。
他的說法是：**門檻形式本身就是低效率的那個**，正確形式是圍繞公允價內部掛價。
→ **可驗，而且不需要新資料**：`../arb` 的 `minutes.csv` 有逐分鐘雙邊簿口。
   把「穿過帶就吃」換成「內部報價、只有當它穿過對手最佳價才送出」重算，
   看可捕獲金額的量級變不變。這是同一份資料上比兩個規則，對資料窗免疫。

*(c) 「找到並進得去低效率市場本身就是 alpha」——這是鏈上線的論點，用他的話講*。
配合第 4 篇的「capacity vs skill」，兩篇講的是同一件事：
**大機構有能力但容量太小所以不做的利基。** 這不是安慰，是他整個
Small Trader Alpha 系列的前提。

*(d) 「2 × 0 還是 0」對上我們的 V7 歷史*：WQ101 的 75 個 alpha、86 個新特徵、
三輪同源 A/B 全部不過——我們的結論是「同源資料飽和」。他的框架給同一件事
另一個說法：我們一直在調乘數，而分子沒有變。

## 4. Where's the edge?（2024-10-12，免費段）

**他主張**
你賺錢是因為別人被**約束**，不是因為你比別人聰明。他列了四類約束：
營運麻煩、**容量 vs 能力**、風險溢酬、薄利。

「容量 vs 能力」那條他寫成一句話：**知道的人不在乎，在乎的人不知道。**
利基交易的容量有限，所以有能力的大機構直接放棄。
機構級的技能 + 散戶級的規模＝這個組合是可行的。

他還說：**新 alpha 的 edge 是加法，執行/ML 的 edge 是乘法。**

以及一個操作面的：把多套策略的工具都準備好，**在條件對的時候輪流上**
（山寨季就去山寨簿口、資金費好就跑資金費、BTC 瘋了就在那裡報寬價）。
門檻是「有沒有先把工具建好」。

**對照我們的**
- **「輪流上」就是我們的組合層在做的事**，但我們目前是**同時跑**所有線，
  不是**條件化輪換**。§1.07 量到只有 V7 與舊線有正的邊際貢獻，
  加低夏普的線會稀釋（V7 單獨 t=2.97 → V7+SDV t=2.32）。
  → 他的版本是：**不要同時開，要按條件切換。** 這需要一個「什麼條件下開哪條線」
     的規則，而我們的生存條件層（ADX、Donchian、SMA 派損益）本來就是為此建的，
     只是目前只當儀表看，沒有接到資金分配上。
- 「加法 vs 乘法」給了一個排序規則：我們現在在做的鏈上線是**加法**（新 alpha 源），
  而 Nautilus / 執行改善是**乘法**。加法優先。

## 5. Small Trader Alpha #6: Perpetual Arbitrage（2024-07-10，免費段）

**他主張**（只記對我們有用的三點）
1. **穩定幣基差要用各交易所自己的價格**，不能用全域價。USDC 脫鉤時
   Coinbase 到 93 分、KuCoin 也偏離很多——用全域價等於在賭脫鉤。
2. **合約正規化沒有萬用公式**：資金費累積、各所上限不同、指數構成不同。
   他的做法是對特定交易所對直接關掉或拉高門檻，並且給每個配對一個
   「相似度信心分數」來決定下多大。
3. **出場不該等回到均值**：期望回歸幅度隨 z 分數下降，而價差波動大致不變
   → **越接近均值，風險報酬比越差**。所以要有第三個參數：出場 z 分數。

**對照我們的**
- 第 3 點是**現在就能在既有錄製資料上重跑的參數**。§0.75 的凍結判準用的是
  「回到半個帶以內」＝等於回到均值附近。加一個出場門檻掃描，
  資料是 `../arb` 既有的 `minutes.csv`，不需要新錄。
  **注意**：這是掃參數，所以掃的程序本身要進樣本外
  （mistake.md 2026-09-09：報「前半選到什麼」，不只報「我選的在後半如何」）。
- 第 1、2 點是機制細節，對**未來** HL↔CEX 的校準實驗直接有用：
  他明講 **DEX 的資金費週期更短（hourly）**，所以 Binance 的永續價
  不能直接換算過去。那正是校準實驗的第一個坑。
